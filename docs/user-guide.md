# 课程智能助教系统使用手册

本文对应当前本地版本。系统支持课程资料、知识图谱、答疑、出题、单次课备课、提问热点和覆盖分析；自动生成需要自行配置兼容的模型 API。当前未实现课程成员登录和授权，仅绑定本机运行。

## 1. 首次安装

准备 Git、Python 3.12+、Node.js 22.12+。以下使用 Windows PowerShell，在希望存放项目的目录执行：

```powershell
git clone https://github.com/yu10032/nlp.git
cd nlp
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt -e "./backend[dev]"
npm.cmd --prefix frontend ci
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
```

仓库根目录包含 `README.md`、`backend/`、`frontend/` 和 `scripts/`。原开发电脑对应 `D:\code_ai\NLP\work`，队友克隆后默认叫 `nlp`；后续命令都在这个根目录执行。

可选创建手工示例课程：

```powershell
.\.venv\Scripts\python.exe -m ta_backend.seed
```

该示例用于熟悉操作，不是正式课程知识库。无需下载模型权重，也无需配置在线 API，就可以使用资料、图谱、检索和手工教学内容流程。

GitHub 不包含开发电脑上的数据库、课程原件、API 密钥或生成记录。新克隆不会自动出现“自然语言处理 · 知识体系”课程。只有取得对应《NLP知识体系》原件后，才可使用专用导入命令：

```powershell
.\.venv\Scripts\python.exe -m ta_backend.import_curriculum "D:\课程资料\NLP知识体系.docx"
```

将路径替换为实际文件路径。脚本导入独立课程及预置手工教学草稿，已有该课程时保留编辑；其他课程原件请通过资料页上传，不套用该脚本的预置节点。

## 2. 启动与关闭

打开两个 PowerShell 窗口，分别进入仓库根目录。

第一个窗口启动后端：

```powershell
.\scripts\start-backend.ps1
```

第二个窗口启动前端：

```powershell
.\scripts\start-frontend.ps1
```

打开 [课程智能助教](http://127.0.0.1:5173)。后端接口文档为 [API 文档](http://127.0.0.1:8000/docs)。两个终端需保持运行；关闭时分别按 `Ctrl+C`。浏览器标签页关闭不会停止服务，下次运行也不用重复创建虚拟环境或示例数据。

如 PowerShell 阻止执行脚本，可直接在根目录运行相应命令，无需改变系统执行策略：

```powershell
# 第一个窗口
.\.venv\Scripts\python.exe -m uvicorn ta_backend.main:app --reload --host 127.0.0.1 --port 8000
```

```powershell
# 第二个窗口
npm.cmd --prefix frontend run dev
```

## 3. 配置在线生成 API

首次配置时复制模板，已有 `.env` 时直接编辑，不覆盖现有数据库等设置：

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
notepad .env
```

填写以下四项：

```dotenv
TA_GENERATION_PROVIDER=external
TA_LLM_BASE_URL=https://你的服务地址/v1
TA_LLM_API_KEY=你的密钥
TA_LLM_MODEL=供应商提供的准确模型ID
```

基础地址包含供应商要求的版本前缀，不要填写末尾的 `/chat/completions`；后端会自动追加。服务应兼容 Chat Completions，支持 `response_format: {"type": "json_object"}`。保存后停止并重新启动后端，再刷新页面。若暂时不使用，设置 `TA_GENERATION_PROVIDER=disabled` 并重启后端。

同一配置支持答疑、出题、备课自动起草。API 不负责自动确认图谱，也不会启用句编码器或自训 MLP。当前名称/别名和 TF-IDF 匹配仍是词面基线。

点击生成会向配置服务发送问题、目标知识点和相关课程片段；备课还会发送教学目标、课时及所选例题。请使用允许发送的资料。生成结果仍是待审核草稿，需要教师核对内容、引用和教学适用性。

第二阶段已有出题、备课少量真实调用记录，答疑未单独实测；更换供应商或模型后应先用少量资料验证。不要将密钥发到聊天、写入前端或提交到 Git。

## 4. 选择课程并建立资料与图谱

1. 在左上角选择课程，或点击旁边的 `＋` 新建课程。
2. 进入“课程资料”，上传 DOCX、文本 PDF、TXT 或 Markdown，单文件不超过 20 MB；PDF 不超过 100 页。
3. 等待解析完成，检查原文片段、章节、页码和警告。扫描 PDF、图片和不可提取的公式需要人工处理，不能把空白提取结果当作资料已读完。
4. 从片段点击“建立知识点”，或到“知识图谱”添加知识点，核对名称、别名、定义和来源后确认。
5. 按需添加和审核“包含”“使用”“先修”等知识关系。先修关系不允许成环；检索扩展只使用有效的已确认关系。

点击图谱节点可以查看定义、关系和课程依据，再通过“查看原文”核查来源。资料换版使用“更新版本”，保留旧版本；相关教学内容旧审核会失效，需要重新核查。

## 5. 课程答疑

1. 输入教学问题，按需勾选补充已确认图谱邻域，点击“查找依据”。
2. 核对候选知识点，可人工确认零个或多个关联；没有合适关联时不要强行选择。
3. 阅读课程依据，选择实际支持回答的引用。资料不足时补充资料或说明缺失。
4. 手工编写正文；API 可用时也可点击“生成答疑”，然后人工修改。
5. 保存草稿，填写审核人并核对正文和引用后审核通过；可查看版本与审核记录并导出 Markdown。

修改正文、引用、关联节点或更新相关资料后，需要重新审核。这里的审核人名称由操作者填写，当前没有账号认证，不等同于正式课程权限控制。

## 6. 辅助出题

1. 进入出题页面，新建题组并填写标题。
2. 按章节或名称筛选，选择 1–5 个已确认的具体知识点。
3. 设置单选或简答题型、数量及难度，每组最多 5 题；点击“查找课程依据”。
4. 无 API 时手工编写题目；API 可用时可自动起草。逐题检查题干、参考答案、解析、知识点和引用。单选题应有四个不同选项，答案使用 A/B/C/D。
5. 保存草稿并审核。必要字段、题目关联和引用、组内近重复题干等不满足要求时，按页面提示修正；审核后可导出 Markdown。

已有题组在“课程题库”打开。题组修改或退回审核会使引用它的已审核教案失效。

## 7. 单次课备课

1. 进入备课页面，新建备课，填写标题、目标知识点、教学目标和重点问题。
2. 设置 5–240 分钟课时，查找课程依据；手工编写或使用 API 起草。
3. 编辑课堂环节，填写讲解内容、活动、例子、时长、知识点和引用；最多 12 个环节，可增删和排序。
4. 如需课堂练习，从已审核题组中选择。当前关联单位是整份题组，不是跨题组逐题组卷。
5. 检查各环节分钟数之和等于总课时，核对依据和例题，保存并审核后导出 Markdown。

已有内容在“已存备课”打开。关联例题失效时移除并重新选择有效题组，然后重新审核；不要只修改状态而跳过内容核对。

## 8. 提问热点、覆盖与模型实验

- **提问热点**：每行粘贴一条问题，一次最多 50 条。导入后逐条核查知识点建议，确认关联或保留无关联，并可跳转答疑。页面统计最近 100 条提问的节点频次，区分人工确认与待确认预测，不代表全课程累计热点或语义聚类。
- **知识点覆盖**：查看已确认具体知识点的资料、已审核题组和备课覆盖。可从缺口跳转补题或备课。只选择目标但没有在具体题目或环节中关联，不会算作有效覆盖；草稿和失效审核不计入正式覆盖。覆盖率不代表学生掌握程度。
- **模型实验**：输入同一问题比较名称/别名与 TF-IDF 基线。分数用于关联排序，不是答案正确概率；固定句编码器、自训 MLP 和正式模型评测仍待接入。

## 9. 数据保存、更新与协作

默认 SQLite 和上传原件保存在 `data/runtime/`，模型产物保存在 `artifacts/`。日常重启保留数据；需要备份时停止后端，将本地 `.env` 和 `data/runtime/` 复制到受控位置，不上传到公开仓库。数据库与上传文件应一起保存，单独复制数据库不能恢复全部原文。

队友克隆后安装自己的依赖、初始化自己的数据库、配置自己的 API 凭据；共享真实课程资料与数据库需通过受控渠道。当前无需分发模型权重。后续启用自训模型时再按对应模型版本单独分发权重、编码器信息和配置。

更新代码前先处理自己的未提交修改，再执行：

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt -e "./backend[dev]"
npm.cmd --prefix frontend ci
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
```

升级数据库前先备份，完成后重启前后端。不要在 `.env.example` 填写真密钥；私人笔记、截图和数据放在被忽略的 `private/`、`tmp/` 或 `data/runtime/` 中。提交前用 `git status --short` 和 `git diff --cached` 检查内容，`.gitignore` 不会清除已提交的文件或历史。

## 10. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 浏览器打不开 | 检查两个终端是否仍运行，访问 `http://127.0.0.1:5173`；确认从仓库根目录启动 |
| 页面出现接口错误或加载不到课程 | 检查后端终端；确认依赖安装成功、已执行 Alembic 升级，再打开 `http://127.0.0.1:8000/docs` |
| 端口占用 | 停止之前启动的本项目服务后重试；不要随意结束其他程序 |
| 生成按钮不可用 | 检查 provider 是否为 `external`、地址/模型/密钥三项是否填写，重启后端；查找依据并满足页面必填要求 |
| API 连接、认证、模型或额度错误 | 按页面提示核对地址、密钥、模型与账户额度；基础地址不重复填写完整接口路径，避免在截图或日志中泄露密钥 |
| 生成超时或返回格式不符 | 检查网络和服务兼容性，稍后重试或手工编辑；客户端请求超时为 60 秒 |
| 没有课程依据 | 检查课程是否选对、资料是否解析完成、知识点是否有有效来源；需要时补充资料和确认关联 |
| 找不到知识体系课程或原件 | GitHub 不分发本地原件和数据库；先用 `seed` 示例，或取得原件后显式导入 |
| 审核不通过或覆盖没增加 | 按提示补齐正文、答案、时长、具体项知识点和引用；确认审核有效，修改来源或例题后需重新审核 |

开发检查运行 `.\scripts\check.ps1`，验证后端业务、Python 格式及前端类型与构建。当前尚未完成教师教学质量验收、正式模型实验和公网部署验收，实施记录见[第二阶段记录](phase-2.md)。
