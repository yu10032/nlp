# 开发分工与顺序

需求原文保留在 [requirements](requirements/项目简要概述.md)，以 [项目大纲](requirements/项目大纲_4人2至3周.md) 定义业务范围。

| 主责 | 主要目录 | 下一步交付 |
| --- | --- | --- |
| A 前端与图谱 | frontend | 图谱候选修订、问题列表与审核交互 |
| B 后端与部署 | backend、deploy | 资料解析、课程成员、问题数据与审核记录 |
| C 匹配与分析 | training、data/annotations | 共同试标、正式家族划分、句向量基线与匹配头训练 |
| D 生成与教学工具 | backend/src/ta_backend/services | 供应商客户端、共享证据构建、答疑/题目/备课结构 |

共享模型、接口和迁移由实际修改者维护，涉及其他成员时先对齐字段，避免各自重复建立数据对象。

## 迭代安排

1. **第一阶段资料与最小链路**：本地上传、来源、图谱修订、检索与人工审核已实现，详见 `phase-1.md`。正式课程原件、真实生成请求、登录与服务器验收仍待补齐。
2. **图谱与答疑**：候选抽取、关系确认、普通检索与单问题答疑。先用基线关联，保留教师纠正入口。
3. **训练与批量提问**：冻结正式家族划分；名称、句向量、自训头比较；保存机器预测和人工确认，完成相似组与热点统计。
4. **出题、备课与审核**：本地主要流程已实现，新增教学结构、审核、Markdown 导出与覆盖联动，详见 `phase-2.md`；继续做真实供应商和教师内容验收。
5. **覆盖联动与实验**：按节点/章节筛选，缺口跳转；接入真实权重、训练曲线、问题级指标和错误案例。
6. **上线与演示**：完成登录和成员授权、持久化部署、HTTPS 与外部设备完整流程验收。

正式评测先分别测候选召回和候选内排序，再报告多标签关联结果及无合适节点误关联比例。
固定比较候选集、编码器与资料版本，验证集选阈值，测试集留到冻结后运行。示例数据不参与正式结论。

## 本次骨架的验证边界

- 必须验证可启动、数据库迁移、课程隔离、来源读取、空范围、覆盖过滤与名称基线行为。
- 前端完成类型检查和生产构建，并对图谱点选、覆盖跳转、基线请求和新建课程做浏览器检查。
- 不做与当前阶段无关的哈希核验、全目录扫描、外部模型下载或正式训练。
