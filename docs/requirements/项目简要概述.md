# 课程智能助教系统简要概述

更新日期：2026-10-27。本文概述项目定位、功能、技术与实施方式。项目当前处于方案设计阶段。详细设计见[正式项目大纲](项目大纲_4人2至3周.md)。

## 1 项目定位

本项目拟开发一套**融合课程知识图谱与自训匹配模型的智能助教系统**，主要服务教师和助教，帮助整理学生提问、查找课程依据、准备答疑、出题与备课。

系统首先面向自然语言处理课程，支持上传课程资料，并通过独立的课程空间扩展到其他课程。核心业务围绕教师的教学准备与审核展开，与面向学生自主学习、练习推荐的助学系统形成区分。

## 2 主要功能

| 编号 | 功能 | 简要说明 |
|---|---|---|
| 1 | 交互式课程知识图谱 | 从资料建立课程知识点与关系，支持搜索、点击、修订和来源查看 |
| 2 | 图谱关联的课程答疑 | 将问题关联到图谱节点，结合资料生成带引用的答疑草稿 |
| 3 | 批量提问与问题热点 | 批量导入提问，整理相似问题，展示知识点热点与原始问题 |
| 4 | 按知识点辅助出题 | 选择知识点，生成单选题或简答题及答案解析，由教师审核 |
| 5 | 备课与课堂答疑提纲 | 根据章节、教学目标与时长，生成单次课提纲和例题建议 |
| 6 | 模型与检索实验对比 | 展示训练记录、测试结果，并比较基础匹配与自训模型的输出 |
| 7 | 知识点覆盖检查 | 查看知识点是否已有资料、已审核题目和备课内容，定位缺口 |

七项功能共用课程、知识点、资料和审核记录。例如，教师可以从热点知识点发起答疑，再选中该节点出题、备课，最后检查相关内容的覆盖情况。

## 3 技术方案

整体采用 **外部大语言模型接口（API）＋自训知识点匹配模型＋知识图谱与检索计算** 的混合架构。

| 技术部分 | 作用 |
|---|---|
| 外部生成 API | 提出概念与关系候选，基于资料起草答复、题目和备课提纲 |
| 自训匹配模型 | 判断问题与候选知识点的相关性，参与节点关联、排序和图谱高亮 |
| 图谱与检索 | 完成实体归并、资料召回、邻域查询、问题聚合和覆盖统计 |
| 前后端服务 | 提供在线操作、引用预览、人工审核、导出与课程隔离 |

建议技术栈：前端 Vue 3 与交互式图库，后端 FastAPI，训练使用 PyTorch；关系数据库和持久化文件保存资料、图谱、索引及权重。API 密钥由后端管理。

## 4 自主训练内容

自主训练的核心任务是**问题与知识点匹配**。模型接收“问题文本＋候选知识点名称与解释”，输出关联分数。

实现时复用并冻结预训练句编码器，自主编写和训练小型多层感知机（MLP）匹配头。训练数据由人工确认的问题—知识点正负样本对构成，包含同义表达和容易混淆的概念。训练成果包括模型代码、权重、配置、日志及评测结果。

数据按问题家族划分训练、验证和测试集，同一问题的改写不能跨集合。与名称匹配、固定句向量相似度比较，分别检查候选召回、节点关联和错误案例。训练范围是任务匹配头，不等同于从头训练大语言模型；效果是否提升以实验为准。

## 5 实现流程

1. **资料入库**：解析 DOCX、文本型 PDF 等资料，保存章节、片段和来源。
2. **建立图谱**：API 提出实体关系候选，程序归并与校验，教师确认关键关系。
3. **处理提问**：召回候选节点，自训匹配模型进行匹配，教师可修订关联和相似问题组。
4. **生成教学内容**：结合课程证据完成答疑、出题和备课草稿，保留引用与节点链接。
5. **审核与检查**：教师编辑、审核和导出，系统计算覆盖并提供缺口跳转。
6. **部署与展示**：将后端、自训权重和资料部署到服务器，提供网页链接及实验展示入口。

本地完成训练后，模型可以部署到服务器供网页调用。教师无需在自己的电脑上安装训练环境。

## 6 分工与周期

团队 4 人，计划 2–3 周：A 负责前端与图谱交互，B 负责后端、资料和部署，C 负责自训匹配模型训练与问题分析，D 负责生成 API、答疑、出题和备课；全员参与数据标注与内容核查。

第一周打通资料、图谱、基础答疑和模型初训，第二周接通七项功能并完成测试、上线与报告；第三周如有，优先修复和第二课程验证。通过限定主题规模、小批量出题和单次课备课控制工作量。

## 7 项目亮点与预期成果

项目将训练结果用于真实知识点关联，以图谱连接答疑、出题、备课与覆盖检查，并借助 API 提供生成能力。预期交付可访问系统、训练与算法源码、模型权重、示例课程、对比实验和使用说明。

生成内容须由教师审核，图谱关系需有来源。提问热点仅反映当前样本分布，覆盖率表示内容关联情况，均不能直接证明学生掌握程度或教学质量。
