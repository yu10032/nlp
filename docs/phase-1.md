# 第一阶段：资料到可审核答疑

范围依据：研究基线 §0.3、§4、§6–7、§10.2 的 D1–D2 最小链路。原研究文档保留原状，实施事实记录在本页。

## 本阶段交付

1. 上传单个 DOCX、文本 PDF、TXT、Markdown；限制 20 MB、PDF 100 页、DOCX 解压元数据总量 100 MB，检测格式与失败状态。首版使用进程内后台任务，不把它描述为生产任务队列。
2. 按自然段、标题、表格和页面保存来源。长段落再切分，保留少量邻接文本；图像与不可提取公式提示人工检查。
3. 资料更新保留旧版本和原文件；解析失败时旧有效版本继续使用，成功更新时关联审核失效。
4. 图谱节点创建/编辑、来源关联与确认；关系候选、确认/驳回；一跳检索只使用来源有效的已确认关系。
5. 问题持久化、名称和 TF-IDF 开发基线、人工零/多节点确认；机器预测单独保留。
6. 答疑证据检索、在线 JSON 适配、禁用模式、手工编辑、版本快照、审核和 Markdown 导出。
7. Vue 工作台去除装饰眉题和编号，以资料阅读、图谱与原文、正文与依据并列布局组织操作。
8. 24 条待核查的开发问题、标注指南、数据库迁移、后端业务测试与本地容器部署配置。

## 与研究建议的明确取舍

- 沿用已有资料版本表表达 `DocumentVersion`，不重复建立一套资料模型；稳定 `document_id` 关联版本。
- 别名继续使用节点 JSON 数组；当前规模没有单独别名实体的业务需求。
- 第一阶段先使用不需下载编码器的名称与 TF-IDF 基线；B1 句向量与 M1 权重接入放到下一阶段，不将 TF-IDF 称作 B1。
- 不实现哈希字段、权重核验或完整性清单；用版本、ID 和修订快照追踪业务变化。
- 当前节点 PATCH 保存完整表单，减少多种不一致写法；契约对调用方明确说明。
- 本地审核一步完成，保存真实版本和操作者填写名称；正式课程成员权限尚未实现。

## 验证范围

`scripts/check.ps1` 验证后端关键业务、格式和前端类型/构建。当前后端测试涵盖文件解析、伪装格式、扫描 PDF、课程边界、候选关系、先修环、无依据、预测保留、审核失效、版本冲突、历史来源和重启保存。
在线适配器使用 MockTransport 验证请求与输出协议，未代替真实供应商调用。
浏览器使用独立数据库验证上传、图谱编辑、关系审核、来源回跳、答疑编辑/审核/导出状态，以及桌面和手机布局。截图保存在 `.impeccable/review/`，不作为正式课程实验。
独立视觉评审提出的三项问题已按真实浏览器复测：未保存答疑在侧栏核查原文后仍保留、长文档引用进入视口、手机图谱控件不覆盖节点。子代理最终回传因额度限制中断，最后的定向复核由主线程完成，结论只覆盖这些修正。

## 后续依赖
