# 课程智能助教系统

以课程知识图谱连接资料、问题匹配与教师审核。第一阶段按[研究基线](docs/NLP智能助教系统_开发前决策与技术实施基线_研究版.md)的 D1–D2 最小链路实施。

## 当前功能

- 上传 DOCX、文本 PDF、TXT、Markdown，保留原文件、章节/段落/页码和资料版本；解析失败与部分提取有明确报告。
- 创建、编辑和确认知识点，查看原文，建立并审核知识关系；先修关系不允许成环。
- 用名称与 TF-IDF 开发基线关联问题，分开保存原始预测和人工确认；不强制匹配。
- 查询同课程证据，可补充已确认的一跳邻域；在答疑区并列查看原文与编辑正文。
- 创建、编辑、审核和导出答疑；修改正文/引用/节点或更新资料后，旧审核失效，历史版本和审核记录保留。
- 接入可配置的在线 JSON 生成适配器；未配置时支持检索与手工编辑，不发送资料。
- 延续覆盖与实验页面；出题、备课、批量提问在后续阶段实现。

当前名称/TF-IDF 为词面基线，固定句编码器与自训 MLP 尚未加载。没有正式模型指标或正式课程验收结论。

## 当前完成情况与使用边界

当前可用于本地整理课程资料、维护知识图谱、查找答疑依据，以及由教师编辑和审核答案。开发与浏览器演示使用手工示例数据，不能据此判断真实课程的匹配效果。

| 功能 | 当前状态 | 是否依赖在线 API |
| --- | --- | --- |
| 课程与资料管理 | 可新建课程，上传和解析资料，查看原文片段与历史版本 | 否 |
| 知识图谱 | 可手工创建、编辑和确认知识点，关联来源，建立和审核关系 | 否；接入 API 后仍需人工维护 |
| 问题匹配与证据检索 | 可使用名称/别名和 TF-IDF 基线，补充已确认的一跳图谱邻域，人工确认关联 | 否；生成 API 不会替换匹配模型 |
| 手工答疑与审核 | 可编辑引用和正文，保存草稿、审核、查看历史并导出 Markdown | 否 |
| 自动生成答疑 | 已实现兼容 Chat Completions 的 JSON 适配器，依据课程片段生成正文、引用和待补充事项 | 是；尚未验证真实供应商调用 |
| 知识点覆盖 | 可查看资料、已审核题目和备课内容的覆盖；覆盖不代表学生掌握程度 | 否；出题与备课流程尚未完成 |
| 模型实验 | 可对同一问题比较名称/别名与 TF-IDF 结果；分数用于排序，不是答案正确概率 | 否；尚无正式评测结论 |
| 固定句编码器与自训 MLP | 训练代码已提供，句编码器待配置与验证，MLP 权重尚未接入 | 需单独完成数据、训练与模型接入 |
| 辅助出题、备课提纲、批量提问 | 后续开发，现有页面入口不表示业务已完成 | 仅填写 API 配置不能启用 |
| 公网使用与课程权限 | 当前仅供本地运行，登录和课程成员权限尚未实现 | 需单独开发与部署验证 |

推荐使用流程：

1. 选择或新建课程，在“课程资料”上传资料并检查解析结果。
2. 从原文片段建立知识点，确认定义、来源和知识关系。
3. 在“课程答疑”输入问题，点击“查找依据”，核对关联知识点与原文引用。
4. 手工编写答疑；完成在线 API 配置后，也可点击“生成答疑”获得草稿。
5. 教师核对正文与引用，保存并审核，需要时导出。修改内容或更新相关资料后需重新审核。
6. 在“知识点覆盖”检查资料支撑，在“模型实验”查看词面基线的关联表现。

## 本地运行

要求 Python 3.12+、Node.js 22.12+。以下均在 `work` 操作，本次环境已安装依赖并完成数据库升级。

```powershell
# 首次在其他电脑运行
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt -e "./backend[dev]"
npm.cmd --prefix frontend ci

# 已有工程升级 / 新建数据库
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
# 可选：手工示例课程，重复执行保留现有数据
.\.venv\Scripts\python.exe -m ta_backend.seed
```

两个终端分别执行：

```powershell
.\scripts\start-backend.ps1
```

```powershell
.\scripts\start-frontend.ps1
```

访问 [http://127.0.0.1:5173](http://127.0.0.1:5173)；接口文档 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。
接口统一使用 `/api/v1`。前端开发代理转发 `/api`，生产代理配置见 `deploy/nginx.conf`。

## 生成配置

将 `.env.example` 复制为 `.env`，填写自己的兼容服务配置：

```dotenv
TA_GENERATION_PROVIDER=external
TA_LLM_BASE_URL=你的服务地址及版本前缀
TA_LLM_MODEL=你的模型标识
TA_LLM_API_KEY=仅保存在后端的密钥
```

后端调用 `${TA_LLM_BASE_URL}/chat/completions`，需要支持 JSON 输出。重启后端后启用生成按钮。
没有凭据不会进行真实生成请求；本次只验证了模拟 HTTP 响应，真实供应商、额度和资料许可仍需实际确认。

基础地址应包含供应商要求的版本前缀（如 `/v1`），不要重复填写 `/chat/completions`；模型应支持 `response_format: {"type": "json_object"}`。配置只保存在后端 `.env`，不要把密钥写入前端或提交到仓库。已有 `.env` 时修改对应项，避免覆盖数据库等现有配置。

配置后启动或重启后端，在“课程答疑”先查找依据，再生成并人工核对答案。生成请求会将问题和检索出的课程片段发送给配置的模型服务。API 接入只启用自动答疑，不会自动完成知识图谱、出题、备课或自训模型接入。

## 后续继续开发

按以下顺序推进；每项完成后再更新功能状态，不将计划当作已交付能力。

1. **真实资料与 API 验证**：取得实际课程原件及使用许可，抽样检查解析、知识点来源和检索结果；配置服务地址、模型和凭据，验证真实生成、引用有效性以及超时和失败提示。没有凭据时保持手工答疑可用。
2. **正式标注与数据划分**：核查开发问题候选，形成多人确认的金标准，冻结课程图谱和标签版本；先按 `family_id` 划分数据，再拟合和训练，避免同族问题泄漏。
3. **语义匹配与自训模型**：接入固定句向量基线，训练并接入 MLP 匹配头；在同一数据划分上与现有词面基线比较，记录数据、模型和实验版本及真实指标。
4. **批量问题与提问热点**：补齐批量导入、逐条匹配、人工确认和热点统计流程，验证课程隔离与未匹配问题的处理，再开展正式实验。
5. **辅助出题与备课提纲**：基于课程知识点和有效证据实现生成、编辑、引用、版本、审核和导出，并与覆盖统计联动；内容修改或来源更新后使旧审核失效。
6. **部署与权限**：实现课程成员登录和授权，验证 Docker/目标服务器部署、持久化与备份恢复，配置 HTTPS 后再开放公网。

下一阶段的依赖与既有验证范围见[第一阶段记录](docs/phase-1.md)。当前没有正式训练结果、真实供应商调用验收或服务器上线结论。

原始文件和 SQLite 位于 `data/runtime`，训练产物位于 `artifacts`，均不作为源码提交。
本地课程原件、正式标注、答疑导出、截图与密钥不要混入源码。`.gitignore` 默认排除 `.env` 及其本地变体、数据库、模型权重、常见 Office/PDF 原件、压缩包，以及 `tmp/`、`exports/`、`backups/`、`private/` 等目录。`data/` 仅保留说明、占位文件和明确列出的手工演示样例；新增课程数据或正式标注默认忽略。TXT、Markdown、图片及 JSON 等也可能包含私人内容，应放入 `data/runtime/` 或 `private/`，不要依赖文件扩展名判断是否可公开。

提交前使用 `git status --short` 和 `git diff --cached` 检查实际提交内容。忽略规则不影响已跟踪文件，也不清除 Git 历史；若已有敏感文件被跟踪，需另行取消跟踪并检查历史，已泄露的 API 密钥应撤销并更换。Git 忽略规则不控制在线 API 发送的课程片段，也不影响云同步或 Docker 构建上下文。

当前服务绑定本机；公网部署前需要课程成员登录与授权、HTTPS 和实际服务器验证，详见 [部署说明](deploy/README.md)。
